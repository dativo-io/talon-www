The problem changes after the first AI app

Every new use case becomes its own tiny operations stack.

One bot has a budget spreadsheet. Another retries differently. A coding workflow spans providers. A support agent has its own PII rules. When something fails, teams search provider logs and application traces separately. Talon gives these use cases a common operating and policy layer without becoming the orchestrator.

One operating layer

Use cases stay independent. The operating rules stop being reinvented.

Publicly, Talon operates AI use cases. In configuration and CLI, the concrete object is an agent. Today the strongest shipped proof is request/session evidence, cost views, policy decisions and provider-path history; fleet enable/disable commands are not presented as shipped.

Reliability without policy bypass

A provider failure does not erase the rules.

On supported transient failures such as timeouts, connection errors, 429s and provider 5xx responses, Talon can evaluate an ordered fallback chain. Each candidate is re-checked against effective policy, including sovereignty and budget constraints. If no valid candidate succeeds, the path fails closed and the attempts remain linked in signed evidence.

Trust layer

Why regulated and European teams can trust the operating layer.

These capabilities support the control plane; they are not the product category by themselves.

Privacy controls

Built-in, Presidio-compatible and local scanner engines can inform PII policy on governed request paths.

EU and local sovereignty

EU-strict and air-gap/local controls constrain destinations and record observed runtime facts.

Verifiable evidence

HMAC-signed records are tamper-evident and exportable. They support audits and reviews; they do not make a deployment compliant by themselves.

Honest boundary

Talon controls only the paths it can intercept.

Provider traffic routed through Talon can be governed. Tool schemas visible to the gateway can be filtered. MCP calls routed through Talon interception can be controlled. Local shell commands, file edits, browser actions or direct API calls that bypass Talon remain invisible and uncontrolled.

Client-asserted agent and subagent identity is attribution, not authentication. Session caps remain soft unless atomic reservation exists.
