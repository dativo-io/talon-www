Governed resilience

Outages do not get a policy exception.

On a transient provider failure, Talon can walk an ordered fallback chain. Before dispatch, every candidate is checked against provider and model allowlists, target tool policy, budgets, session context, and sovereignty. Under eu_strict, a non-EU/LOCAL candidate is skipped and recorded rather than silently used.

Fallback configuration EU governance Failover evidence Release notes

Detection where you need it

Keep the governance pipeline. Swap the scanner engine.

The built-in regex scanner remains the zero-config default. When you need names, addresses, fuzzy identifiers, or local-only scanning, select a Presidio-compatible service or a local LLM engine. Talon validates adapter output, normalizes offsets, blocks unverifiable scans in enforcement paths, and records scanner facts in signed evidence.

External scanner reference Local scanner cookbook Boundary contract 
scanner:
  type: presidio   # regex | presidio | http | llm
  endpoint: http://presidio:5001/analyze

# Or keep scanning local
scanner:
  type: llm
  llm:
    base_url: http://127.0.0.1:11434

Fast integration

Start with one base URL change.

Your application can keep using the same OpenAI-compatible SDK. Point the base URL at Talon, send a Talon caller key, and let Talon inject the approved provider credential from its vault. Add fallback and scanner configuration later without changing the application SDK.

Existing appLocal Ollama / air-gapSlack botVendor AI
# Before
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_API_KEY=sk-provider-key

# After
OPENAI_BASE_URL=http://talon:8080/v1/proxy/openai/v1
OPENAI_API_KEY=<talon-caller-key>

# Then inspect proof
talon audit list
talon audit verify --failover
