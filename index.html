Reliability without policy bypass

A provider failure does not erase the rules.

On supported transient failures such as timeouts, connection errors, 429s and provider 5xx responses, Talon evaluates an ordered fallback chain. Each candidate is re-checked against effective policy, including sovereignty and budget constraints.

Operator surfaces

Answer the concrete question from evidence-backed commands.

The public product language is “AI use case.” In configuration and CLI, the concrete identity is an agent or caller.

What is spending?

talon costs --agent <name>

Attributed cost where evidence carries the agent or caller identity.

What happened?

talon audit list --session <id>

Requests, providers, models, denials and session history.

Why was it stopped?

talon audit show <id>

Policy decision, PII findings, routing facts and reason.

Can I trust the record?

talon audit verify <id>

HMAC integrity verification for the stored runtime fact.

Honest boundary

Talon controls only the paths it can intercept.

Provider traffic routed through Talon can be governed. Visible tool schemas and intercepted MCP calls can be controlled. Local shell commands, file edits, browser actions or direct API calls that bypass Talon remain invisible.

Client-asserted agent and subagent identity is attribution, not authentication. Session caps remain soft unless atomic reservation exists.
