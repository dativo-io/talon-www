Why the boundary matters

The model request is often not the consequential event.

Agents increasingly turn model output into actions. A gateway that only observes prompts and responses can miss the moment where a business effect becomes real. Talon’s design center is the boundary it can intercept before that effect is dispatched.

Proposal is not execution

A model seeing or proposing a tool does not mean the business effect should be authorized.

Approval must bind the exact effect

“Approve refunds” is too broad. The useful subject is the exact operation, material payload and destination.

Unknown is a real outcome

If dispatch may have happened but the result is lost, a control plane must not blindly retry and duplicate the effect.

Available now

Talon already governs intercepted tool paths.

Tool schemas visible in LLM requests can be filtered or blocked. MCP tools/call routed through Talon can be intercepted and denied before upstream execution, with signed denial evidence. Data, provider and destination policy remain part of the same control boundary.

Boundary: local shell commands, file edits, browser actions and direct APIs that bypass Talon remain invisible and uncontrolled.

Active product direction

Move from “tool allowed” to “this exact action is authorized.”

The Action Gateway work is converging supported runtime boundaries on one authorization contract: trusted action identity, schema-validated material arguments, ALLOW | DENY | REQUIRE_APPROVAL, exact decision binding, one-use authorization consumption, conservative handling of ambiguous dispatch and verifiable evidence.

Talon owns authorization—not workflow orchestration. External runtimes keep waiting, branching, scheduling and business retries. This is active development, not a claim that every exact-action approval path already ships today.

What Talon is not

Not an MCP gateway company. Not a workflow engine. Not endpoint security.

MCP is one standards-native transport beneath the control plane. External orchestrators keep workflow and waiting responsibility. Talon focuses on deterministic company policy, exact intercepted-action authorization and proof—not on owning every connector or every local effect.
