# AI-assisted documentation contract

The full website build publishes one plain-text Markdown export per canonical docs route at its index.md (including the overview). The synchronized Markdown inputs are the same as the rendered docs: selected stable release, reviewed errata, local website pages, and normalized links. Exports remove Docusaurus front matter and the overview's known presentational wrappers, convert document links to canonical URLs outside code, and add release/source/erratum provenance. They are readable Markdown, not a verbatim Git blob or a complete HTML representation. Code examples are reference material, not permission to execute. Each export is listed with SHA-256 in /talon/docs/markdown-manifest.json. The generated docs llms.txt links to every export, and llms-full.txt concatenates them, with a 10 MiB ceiling. HTML remains canonical; auxiliary files are excluded from HTML sitemaps and declared noindex in hosting headers. No external LLM service or new dependencies.

Every article gets explicit Copy page as Markdown and View Markdown controls. Copy is a user-initiated same-origin fetch and clipboard operation; the view link remains available if clipboard permissions fail. No automated command execution or automatic AI context transmission. No chatbot or skill installer.

Umami receives only the current page and fixed event categories: Docs Markdown Copy (click only), Docs Markdown View, Docs Search (open/result/explicit no-results Enter). Search text, clipboard contents and result identifiers are not sent by these events; Do Not Track is respected. Result pointer navigation may also generate the existing navigation-click signal; count these separately, not as unique users. Measure engagement, not installations or successful execution. Native tests cover exports and privacy; browser test checks content and exact bytes using a clipboard stub. Actual browser clipboard permissions, production hosting content types and Umami dashboard still require live acceptance.

Local full build is authoritative: bash scripts/build-site-with-docs.sh. Direct Docusaurus dev server does not generate the export files. Release promotion requires regenerating these files from the approved manifest, never hand-editing published output.
