What gets recorded

Compact records for the decisions that matter.

Talon evidence is designed for incident review, customer security questions, and auditor handoff — not just dashboard charts.

🧾

Decision context

Caller, tenant, policy version, allow/deny/redact decision, reason, and the runtime path that produced it.

🔎

Scanner context

PII findings plus scanner type, engine identity, version, scan duration, and typed failure kind when an external or local engine is used.

🔁

Failover context

Failed provider attempts, selected fallback or fail-closed outcome, policy-skipped candidates, correlation ID, and failover group ID.

Provider failover evidence

Show that reliability did not bypass governance.

When a transient provider failure engages a fallback chain, Talon writes one signed attempt record per failed provider and exactly one terminal record for the selected fallback or the fail-closed result. Candidate policy skips are distinct from runtime failures, so a review can see whether sovereignty or caller policy prevented dispatch.

Scanner evidence

Know which detection engine made the decision.

External and local scanner engines stay behind the same governed Talon paths. Evidence records the engine identity and typed scanner failures instead of silently pretending a scan succeeded. In enforce mode, an unverifiable scan blocks egress rather than falling back to a weaker hidden path.

Sovereignty posture report

Turn evidence into a reviewable data-residency artifact.

The sovereignty report combines declared config — routing mode, deployment mode, gateway providers, and allowed egress — with runtime evidence such as observed destinations, egress denials, and routing rejections. It is supporting evidence, not a legal determination.

Report overviewAir-gap guideExport runbook
talon compliance sovereignty \
  --format json \
  --tenant acme \
  --gateway-config talon.config.yaml \
  --output sovereignty.acme.json

talon compliance sovereignty \
  --format html \
  --output sovereignty.acme.html

Review workflow

Export, sample, verify, and explain runtime posture.

For a customer, DPO, security, or auditor review: export a period, sample evidence IDs, verify signatures, verify linked failover chains when relevant, and attach the sovereignty posture report.
